# 

React (Vite, Tailwind)  ->  Node.js + Express gateway  ->  FastAPI ML service  ->  trained LSTM (.keras)
      :5173                        :4000                          :8000

React never talks to the ML service. Node is the only API the browser sees. The LSTM is trained separately in Google Colab and loaded once when FastAPI starts. No prediction value is ever hard-coded or generated by a mock: if the model is missing, the prediction endpoint returns a clear error and the UI shows "Prediction unavailable" while everything else keeps working on sample data.

## 2. Place the trained LSTM model and scaler

Copy the files exported from Colab:

```
ml-service/models/stock_lstm.keras        (an .h5 file also works: set MODEL_PATH)
ml-service/preprocessing/scaler.pkl       (joblib or pickle of a fitted scikit-learn scaler)
```

Then edit `ml-service/model_config.json` so it matches how you trained:

| Key | Meaning |
| --- | --- |
| `sequence_length` | Window length fed to the LSTM (must match the model input shape) |
| `features` | Ordered feature columns used in training. Supported: `open high low close volume return sma_N ema_N rsi_N macd macd_signal` |
| `target_feature` | Feature the model predicts (must be a price such as `close`) |
| `output_mode` | `single_step` (predict next day, applied recursively) or `multi_step` (model outputs N days at once) |
| `max_horizon` | Largest `days` accepted |
| `min_history_rows` | Minimum history rows required |

The scaler must be fit on the feature matrix in the same column order as `features`. On startup the service checks that the model input shape and the scaler feature count agree with the config and reports any mismatch in `/health`.

Replace the files and call `POST http://localhost:8000/model/reload` (or restart uvicorn). The frontend and Node backend need no changes.

To train a compatible model in Colab, upload `ml-service/features.py` and `ml-service/scripts/train_reference.py`, then run:

```bash
python train_reference.py --csv VIC.csv --features close --seq 60 --out .
```

The script saves `models/stock_lstm.keras`, `preprocessing/scaler.pkl` and `model_config.json`. Custom notebooks work as well as long as they use the same preprocessing. If you train with extra features, import `build_features` from `features.py` so training and inference use identical code.

Historical data: Node sends its last 400 daily rows in each `/predict` call. If you prefer, put `ml-service/data/VIC.csv` (columns `date,open,high,low,close,volume`) and omit history.

## 3. Test the prediction API

```bash
curl http://localhost:8000/health
curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" \
  -d '{"symbol":"VIC","days":7,"history":[{"date":"2026-01-02","close":100000}]}'
curl "http://localhost:4000/api/stocks/VIC/prediction?days=7"
```

Response (Node adds `source`, `days` and `disclaimer`):

```json
{
  "symbol": "VIC",
  "predictions": [{ "date": "2026-09-30", "predicted_price": 102500.0 }],
  "meta": { "model_name": "stock_lstm", "last_actual_close": 102500, "has_confidence_interval": false }
}
```

Error codes returned by Node: `ML_SERVICE_UNAVAILABLE` (503), `ML_MODEL_NOT_READY` (503), `ML_SERVICE_TIMEOUT` (504), `ML_INVALID_REQUEST` (422), `ML_SERVICE_ERROR` (502).

Confidence intervals are never fabricated. If your service later adds `lower` and `upper` to each prediction item, the chart draws the band and the table shows the range automatically.

## 5. Real-time data

The app is not real-time. `MARKET_DATA_PROVIDER=sample` serves deterministic sample prices and the UI says so in the header. To connect a real provider:

1. Add `backend/providers/myProvider.js` exporting `name`, `isRealtime`, `listStocks`, `getStockMeta`, `getHistory`, `getQuote`, `getIndices` (same shape as `sampleProvider.js`).
2. Register it in `backend/providers/index.js` and set `MARKET_DATA_PROVIDER`.
3. For streaming, call `publishTick({ symbol, price, ... })` from `services/marketStream.js` when your WebSocket receives ticks. Clients subscribed to `/api/stocks/:symbol/stream` receive them.

The UI switches from "Sample data, not real-time" to "Live market data" only when the provider sets `isRealtime = true`.

The sticky header carries a ticker tape built from `getIndices()`. The sample provider's `INDICES` list in `backend/data/stocks.js` includes VN-Index, VN30, HNX-Index, S&P 500 and Bitcoin, each with its own rounding step and precision. Add or remove entries there and the tape follows.

## 6. Alpha AI and the agent layer

`POST /api/chat` runs `services/agent/agentService.js`:

1. Detects the symbol and intent (outlook, prediction, technical, news, price, market).
2. Calls tools in parallel: `get_current_price`, `get_historical_summary`, `get_lstm_prediction`, `get_technical_indicators`, `get_market_news`, `get_news_sentiment`, `get_market_overview` (`services/agent/tools.js`).
3. Builds an evidence object. If a tool fails (for example the ML service is down) the failure is recorded and no number is invented.
4. Produces the reply with sections for actual market data, LSTM prediction, technical indicators, news sentiment and AI interpretation.

The chatbot never touches the model directly; predictions come only through the Node prediction service.

Without an API key, replies come from a rule-based composer that only formats the evidence. To connect an LLM, set in `backend/.env`:

```
LLM_PROVIDER=gemini        # or openai
LLM_API_KEY=your-key
LLM_MODEL=                 # optional, set a current model name for your account
```

The provider receives the evidence JSON plus a system prompt (`services/llm/prompts.js`) that forbids inventing numbers. If the LLM call fails, the answer falls back to the rule-based composer. To add another provider, add one function to `services/llm/index.js`.

## 7. Database preparation

Services keep state in memory (watchlist, alerts, paper account) so the app runs with no database. `backend/db/schema.sql` contains PostgreSQL tables for User, Stock, HistoricalPrice, Prediction, Watchlist, Portfolio, PortfolioTransaction, Alert, News and ChatMessage. `DATABASE_URL` is read into `config.js`; replace the in-memory functions in `portfolioService.js` and `newsService.js` with queries when you are ready. For MongoDB, the same entities map directly to collections.

## 8. Frontend UI/UX and languages

The front end is a dark-first financial terminal UI (see [docs/ui-ux-redesign.md](docs/ui-ux-redesign.md) for the full design system, the component inventory and the honest status of the requested skill packages).

- **Languages:** English and Vietnamese, switched from the header and stored in `localStorage` under `alpha.lang`. All copy, table headers, chart legends, nav items and chat placeholders re-render instantly; numbers and dates follow the language too. Dictionaries live in `frontend/src/locales/{en,vi}.json`. No i18n dependency is used - the provider is `frontend/src/i18n/index.jsx`.
- **Command palette:** `Ctrl`/`Cmd` + `K` searches stocks, navigates pages, runs actions, or sends the typed text straight to Alpha AI.
- **Export:** on a stock page, download the history plus the LSTM predictions as CSV, or open a print-styled summary report and save it as PDF from the browser.
- **AI confidence and insights:** a collapsible drawer beside the chart breaks the trend down into real technical factors (moving averages, RSI crossover, MACD histogram, volume spike, Bollinger position) with a factor-agreement score that is clearly labelled as a read of those factors, never as model internals or a fabricated confidence interval.
- **Price alerts:** set a target on a stock page; the widget polls the quote and raises a notification toast when the level is crossed. Alerts are the same records the portfolio page manages.
- **Theme:** dark by default, light available from the header toggle, applied before first paint.
- **Routes and the 404 page:** an address that matches no page renders `frontend/src/pages/NotFound.jsx` instead of silently redirecting to the dashboard. It offers *back to the previous page* (with an `history.state.idx` guard that falls back to the dashboard when there is nothing to return to), lists the addresses that are not implemented yet (`/technical`, `/screener`, `/compare`, `/reports`, `/settings`), and links every supported stock page. A deep link written the API way (`/stocks/MWG`) is recognised and offered as a working `/stock/MWG` link.
- **Number cards:** `frontend/src/components/Stat.jsx` plus the `.stat-label` / `.stat-value` classes keep long amounts such as `500.000.000 VND` inside their card: the cell is `min-w-0`, labels wrap and values break instead of pushing out of the grid.
- **Navigation robustness:** an `ErrorBoundary` wraps the routes so a render error shows a recovery screen (retry, back, home, reload) instead of a blank page; `useApi` aborts its request on unmount; and changing route closes overlays, clears any scroll lock and scrolls back to the top, so Back always lands on a visibly fresh page.
- **Candlestick chart:** the "Candles" mode on a stock page draws a dense terminal-style chart - thin green/red candles with wicks, a faint dashed grid, dashed guides at the highest and lowest session and a dashed line on the latest session. The choice is remembered in `localStorage` under `alpha.chart-mode`.
- **Dashboard layout:** the index cards run across the top; the top gainers and top losers sit side by side in two equal columns (`items-start`, so a growing watchlist never stretches them) and each closes with the average change of its list; market sentiment and the watchlist take the narrower right rail. The mover bodies are a fixed `h-[400px]` (six rows share it, more rows scroll) and the watchlist body is `max-h-[440px] overflow-y-auto`, with sticky headers everywhere - the three cards line up, and a long list scrolls inside its own card instead of lengthening the page. The simulated-account summary is not on the dashboard any more - the portfolio page owns those numbers.

## 9. Notes

- Sample data and sample news are generated locally and clearly labelled. Sentiment uses a keyword lexicon and is a placeholder for a real NLP model.
- Paper trading, risk estimates and the P/L calculator are simulations and never place real orders.
- LSTM output is a statistical estimate, not a guaranteed price and not financial advice.
- Production build: `cd frontend && npm run build`, then serve `dist/` behind a proxy that forwards `/api` to the Node server, or set `VITE_API_URL`.
